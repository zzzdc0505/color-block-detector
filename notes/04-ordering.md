## 1. 先明确：用哪个点排

每个轮廓算出了 `minAreaRect` 的**中心点** `(cx, cy)`，排序就用这个点。

为什么不用外接矩形左上角？两个原因：

1. `minAreaRect` 返回的是**中心 + 尺寸 + 角度**，它压根不保证四个顶点的顺序（不同角度下返回顺序会变）；
2. 色块倾斜时，"左上角"会因为旋转而漂移，同一列的两个块可能被排反。

**中心点是旋转不变的** —— 不管怎么转，矩形中心都在那儿。这是选它的硬理由。

## 2. 单列的情况：按 y 升序就够

```python
blocks.sort(key=lambda b: b["center"][1])
```

真实板子（`demo/board.png`）跑出来：

```
1. 红 (422,75)   2. 绿 (423,120)  3. 红 (422,167)
4. 蓝 (425,218)  5. 绿 (423,272)  6. 蓝 (428,331)
```

y 从 75 递增到 331，干净利落。**注意它们的 x 全在 422~428 之间 —— 这说明是同一列。**

## 3. 多列的情况：只按 y 排会"左右横跳"

这是题目没写清楚的地方：**"自上而下"是一列一列读，还是从左到右一行一行读？**

造一块两列三行的板子试试（`l6_order.py` 会现画一张）：

```
只按 y 排序：  红(195,85) 蓝(635,115) 绿(195,205) 黄(635,235) 蓝(195,325) 紫(635,355)
先聚列再按 y： 红(195,85) 绿(195,205) 蓝(195,325) 蓝(635,115) 黄(635,235) 紫(635,355)
```

第一行是"左、右、左、右、左、右"——x 在 195 和 635 之间反复跳，**编号看着就是乱的**。

所以 `order_blocks()` 分两步：**先按 x 聚成列，列内按 y 升序，列按 x 升序拼起来**（先列后行）。
第二行就是结果：左列 1、2、3 从上到下，然后右列 4、5、6。

> **这里必须主动声明**：题目只说"自上而下"，多列时的读序是有歧义的。
> 我选的是"先列后行"（一列读完再读下一列），并写进 README ——

## 4. "聚列"怎么聚：一个阈值

```python
med_w = np.median([b["size"][0] for b in blocks])   # 块宽的中位数
gap = max(med_w * 1.5, 25.0)
```

按 x 排序后，**相邻两块中心 x 差超过 `gap` 就认为换列了**。

实测数字：这块板的色块宽 98~115 像素，`med_w ≈ 105`，所以 `gap ≈ 158`。
同一列内相邻块的中心 x 差只有几像素（422 vs 428），远小于 158 → 同一列；
两列板子的列间距是 365，远大于 158 → 拆成两列。**两个方向都有 2 倍以上的余量，很稳。**

用 `median`（中位数）而不是平均值，是为了**抗离群值**：万一混进来一个宽度 400 的假候选，平均值会被拉跑，中位数不会。

## 5. 复杂度

排序是 `O(n log n)`，n 是色块数（个位数）。整个函数耗时可以忽略 ——
`find_blocks` 占 9.4 ms 里的绝大部分，排序连 0.1 ms 都不到。

## 6. 代码

```python
def order_blocks(blocks):
    by_x = sorted(blocks, key=lambda b: b["center"][0])      # 先按 x 排

    columns = [[by_x[0]]]
    for b in by_x[1:]:
        if b["center"][0] - columns[-1][-1]["center"][0] > gap:
            columns.append([b])                              # 间距太大 -> 新的一列
        else:
            columns[-1].append(b)                            # 否则归到当前列

    ordered = []
    for col in columns:
        col.sort(key=lambda b: b["center"][1])               # 列内按 y
        ordered.extend(col)
    return ordered
```
