## 1. 掩膜 ≠ 对象

第 3 课得到的掩膜只是一张黑白图，图上"白"是连成片的像素。
但题目要的是"**6 个色块，每个有颜色、有位置、有顺序**"。从"一片白"到"6 个对象"，缺的就是这一步。

`cv2.findContours` 做的事：**沿着白区的边界走一圈，把边界点的坐标存成一个序列**。

```python
contours = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)[-2]
```

- `RETR_EXTERNAL`：只要最外层轮廓（不要"洞里还有洞"的层级关系）—— 这道题够了；
- `CHAIN_APPROX_SIMPLE`：把直线段上多余的点压掉，只留拐点，省内存。

**关键认知**：轮廓是一串点，不是一个"区域"。想算面积、算形状，得自己用点去算。

## 2. 四个特征，四个数

对每个轮廓算四个数，就是这道题的全部"判断依据"：

| 特征       | 怎么算                              | 它回答什么问题                                 |
| ---------- | ----------------------------------- | ---------------------------------------------- |
| 面积       | `cv2.contourArea(cnt)`              | 这东西够不够大？（太小是噪点，太大是地面）     |
| 面积占比   | 面积 / 图片总像素                   | 换成比例后**不受分辨率影响** —— 换台相机也能用 |
| 外接矩形   | `cv2.minAreaRect(cnt)` → w, h, 角度 | 它有多宽多长、歪了多少度                       |
| 长宽比     | `w / h`（把长边当 w）               | 它是"横条"还是"方墩"？                         |
| **矩形度** | `面积 / (w * h)`                    | **它有多像一个规整的矩形？**                   |

### 为什么必须是 minAreaRect，不能是 boundingRect

`boundingRect` 给的是**正着的**外接矩形（不旋转）。板子一歪，正矩形就会把周围一大片空白包进来，
面积不变、外接矩形变大 → **矩形度被人为压低** → 明明是色块却被误杀。

`minAreaRect` 给的是**能转的最小矩形**：不管色块歪多少度，它都紧贴着贴上去，矩形度只反映"形状像不像矩形"。
这也是 `minAreaRect` 返回 `(中心, (w,h), 角度)` 三个量的原因 —— 角度是它的核心价值。

### 矩形度为什么能区分色块和花盆

色块是"印刷出来的矩形"，它的轮廓几乎填满外接矩形 → **0.93 ~ 0.98**。
花盆是梯形/圆的，地面是不规则多边形，反光是碎块 → **0.47 ~ 0.85**。

**这条特征不是"颜色"，是"几何"** —— 这就是为什么它能补上颜色过滤漏掉的干扰。

## 3. 实测：20 个候选怎么掉到 6 个

`l5_contours.py` 在 `demo/board.png` 上收到 **20 个候选**，逐个打印特征，再按三条阈值过滤。

### 留下来的（6 个真色块）

| #   | 色  | 中心      | 面积% | w×h    | 长宽比 | 矩形度 |
| --- | --- | --------- | ----- | ------ | ------ | ------ |
| 5   | 蓝  | (428,331) | 1.67% | 115×60 | 1.92   | 0.96   |
| 6   | 绿  | (423,272) | 1.45% | 112×53 | 2.11   | 0.98   |
| 7   | 蓝  | (425,218) | 1.32% | 108×51 | 2.12   | 0.96   |
| 9   | 红  | (422,167) | 1.27% | 105×52 | 2.04   | 0.93   |
| 10  | 绿  | (423,120) | 1.03% | 99×44  | 2.28   | 0.95   |
| 11  | 红  | (422,75)  | 0.94% | 98×42  | 2.35   | 0.93   |

**长宽比全部 ≥ 1.9，矩形度全部 ≥ 0.93。**

### 被淘汰的（典型四类）

| 候选       | 面积% | w×h     | 长宽比   | 矩形度   | 死在哪一关 |
| ---------- | ----- | ------- | -------- | -------- | ---------- |
| 黄色地面   | 4.39% | 281×116 | 2.42     | **0.54** | 矩形度     |
| 橙色花盆   | 1.30% | 83×69   | **1.20** | 0.90     | 长宽比     |
| 红色反光块 | 0.67% | 97×54   | 1.80     | **0.51** | 矩形度     |
| 窗边小红点 | 0.09% | 20×18   | 1.11     | 0.94     | 面积       |

注意第 2 行：**花盆的矩形度 0.90，比阈值 0.85 还高！** 只靠矩形度杀不掉它，是**长宽比 1.20** 把它拦下来的。
第 4 行更妙：矩形度 0.94 很高，但**面积只有 0.09%**，太小 —— 第一关就出局。

**所以三个条件是互补的，缺一不可。** 任何一个单独用都会放过或误杀。

### 漏斗

```
全部候选 20  →  过面积 16  →  过面积+长宽比 8  →  全过 6
```

三个条件都是"与"关系，所以**先卡哪个、后卡哪个，最终结果完全一样**。
但程序里还是按「面积 → 长宽比 → 矩形度」这个顺序写，因为：

- **面积最便宜**（一次 `contourArea` 就出结果），先用它砍掉大部分；
- 长宽比也便宜；**矩形度最贵**（要先算 `minAreaRect`），放最后 —— 只对幸存者算。

这是很典型的工程习惯：**便宜的判断放前面**。

## 4. 对应到代码

```python
area = cv2.contourArea(cnt)
if not (min_area_ratio * img_area <= area <= max_area_ratio * img_area):
    continue                                    # ① 面积

(cx, cy), (rw, rh), angle = cv2.minAreaRect(cnt)
if rw < rh:                                     # 长边当宽
    rw, rh, angle = rh, rw, angle + 90.0
if rh < 1.0 or rw / rh < aspect_min:
    continue                                    # ② 长宽比

if area / (rw * rh) < fill_min:
    continue                                    # ③ 矩形度
```

注意 `if rw < rh: 交换` 这一步 —— `minAreaRect` 返回的 w/h 不保证长边是 w，
不归一化的话，竖着的色块长宽比会算成 0.4，直接被误杀。

## 5. 一句话总结这一课

> **形态学负责"干净"，几何特征负责"是它"。**
> 颜色告诉你"这是什么颜色"，几何告诉你"这是不是一个色块"。
